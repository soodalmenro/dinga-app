## 확인한 동선과 잠금

- 양쪽 구성 모두12파트를 실제 화면 버튼으로 순서대로 완료했다. 운지의 ‘올렸어요/다 올렸어요’, 박자 완료 대기, 전환 시작/자동 완료, 곡 바로 시작을 사용했다. 평가 패널의 단계 건너뛰기는 사용하지 않았다.
- 기본 구성의 완주하기 잠금은 앞선 코드9파트를 마칠 때까지 유지되며9번째 완료 뒤 열린다. 코스 진행12/12·재연주·이어하기 해제를 확인한다.
- MY의 곡 바로가기는 학습 잠금과 무관하게 유지한다. 코스2/3 내용은 추가하지 않는다. 코스 상세의 중복 곡 항목과 주 단위 마감도 되살리지 않는다.
- 마이크·카메라 거부 조건에서도 모든 파트를 진행할 수 있다. 이것은 실제 연주 성공이나 인식률의 증거가 아니다.

## 발견·수정한 기능 차이

### 전환 단계의 부모 진행 표시

아이디어 레슨 안의 새8마디 전환 화면은 마디별 결과를 표시했지만 부모 레슨 상단 진행 바는0에 머물렀다. 옛 전환 컴포넌트만 부모 진행에 연결돼 있었다. 새 전환도 완료 마디 수를 부모에 전달한다. 다음 전환 단계와 실제→모의 재시작은0으로 돌아가고, 일시정지·속도 변경은 이미 끝낸 마디를 보존한다.

진행 바에 접근 가능한 이름·현재 값·전체 값과 마디/단계 단위를 제공한다. 시각 디자인과 기존 로컬 이미지는 바꾸지 않는다.

### 마지막 코스 파트의 적립 시간

기획3.1과 Figma35:97은 코스 파트 완료를180초로 적립한다. 새12마디 화면은 코스 완주까지 템포 기반90초(기본40%)로 계산해, 기본 구성 코스 전체가2160초 대신2070초가 됐다. 코스 파트에서 끝까지 완주하면180초로 고쳤다.

단독 곡 연습과 부분 종료는 기존 마디·템포 기반 규칙을 유지한다. 종료 이벤트에는 `fromLesson`·`creditedSeconds`를 남겨 시간 적립의 종류를 구분한다. 이것은 실제 연주 시간 측정값이 아니다. 완료 중복 방지·실제/모의 최고 점수 규칙·과거 저장 기록은 유지한다.

## 검증 범위

- `qa/course-walkthrough.cjs`: 두 구성24파트, 기본 잠금 경계, 완료/이어하기/12파트2160초, 기존 로컬 캐릭터 렌더링. `QA_CAPTURE=1`로 화면 캡처 가능.
- `qa/embedded-progress.cjs`: 패널/속도 변경, 다음 전환의 초기화, 실제 입력 중단 뒤 명시적 모의 재시작3개.
- `qa/song-completion.cjs`: 기존7개에125% 코스 완주와 미측정 코스 완주를 더한9개. 단독·부분 종료와 코스 적립의 구분 및 종료 진단 필드도 확인한다. 코스 재시도/125% 완주는 실제 JSON을 내려받아 적립 초와 코스 여부, 부분·완료 이벤트를 확인한다.
- 운영 주소에서도 전체24파트·완료9개·전환 진행2개·핵심 흐름6개를 통과했다. 다운로드 추가 검사2개도 운영 주소에서 통과했다. 로컬의 실제 입력 중단 모의3번째 진행 검사는 운영 결과에 섞지 않는다.
- 전체 회귀·모바일·배포 검증의 최종 결과와 운영 버전은 해당 작업 계획에 남긴다.

## 별도로 남기는 차이와 제한

- 후속 [모달 시각 정리](COURSE_MODAL.md)에서 기본 구성의 파트2 제목을 ‘코드 잡기’로 맞추고, 상단 캐릭터·배지·아이콘·여백을 반영했다. PRD 비교 구성은 기존 제목을 유지한다. 가독성을 위한 기존 폰트·본문 색과 최신12마디 내용은 유지하므로 전체 화면의 픽셀 일치를 주장하지 않는다.
- 본문 대비·모션 줄이기·새 오류/복구 안내는 앞선 품질 보강을 유지한다. 오래된 개발 전달의 보조 글자 색으로 되돌리지 않는다.
- Figma의 ‘반 박’ 표현과 현재 코드의0.6박 허용 오차는 실기 보정 전 기준이다. 박자 허용 오차를 이번 기능 수정에 섞어 바꾸지 않았다.
- 실제 OS 위젯·친구 서버·추가 코스·엄지 인식·오프라인 실행을 이번 묶음에 추가하지 않았다. 실제 인식률과 기기별 권한·발열은 마지막 실기에서 확인한다.
