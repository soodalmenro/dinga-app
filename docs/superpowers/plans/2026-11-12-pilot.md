# 딩가 평가용 버전 개발 계획

11월 17일 리허설과 18일 파일럿에서 참가자가 통기타와 휴대폰으로 출석부터 곡 완주까지 진행하고, 진행자가 참가자별 행동 기록을 회수할 수 있도록 한다. 현재 React + Vite 앱과 브라우저 로컬 저장 방식을 기준으로 한다.

기준 자료는 [기획서](https://docs.google.com/document/d/1ncRvGCZSsE_KISSqRJqXCyYaawHLI1sK1_pGuvFEVxs/edit), [Figma 개발 전달](https://www.figma.com/design/7P8BU0iGlHRnj52Z7q1JBb/?node-id=35-40), [11월 11일 수정 화면](https://www.figma.com/design/7P8BU0iGlHRnj52Z7q1JBb/?node-id=77-6)이다. Figma의 미반영 제안은 평가 동작의 확정 명세와 구분한다.

| 단계 | 실행과 통과 기준 | 최초 추정 |
|---|---|---|
| 1. 기준 점검 | 프로덕션 빌드에서 기존 전체 QA와 마이크 거부 회귀 테스트를 실행한다. 실패 시 화면, 재현 조건, 실제 결과를 기록한다. | 15~30분 |
| 2. 화면과 동선 | 위젯 → 출석 → 코스 → 완주 → 리포트 → 전환 연습 → 원래 리포트, MY → 같은 곡 완료를 따라간다. 확정 흐름의 불일치를 재현하고 수정한다. | 1~3시간 |
| 3. 기록과 예외 | 처음 사용, 같은 날 다시 열기, 권한 거부, 60초 미만·이상에서 나가기, 마지막 단계 이어하기, 참가자 교체를 검사한다. 초기화 전후 진행도와 참가자 번호가 붙은 행동 기록을 확인한다. | 1~2시간 |
| 4. 모바일·배포 준비 | 작은 모바일 뷰포트에서 화면 하단 버튼, 가사, 리포트 스크롤을 점검한다. HTTPS 평가 URL에서 새 세션을 시작하고 새로고침 뒤 기록을 읽을 수 있는지 확인한다. | 1~2시간 |
| 5. 실기 리허설 | 평가용 폰과 통기타로 출석 2초, 미감지 10초, 연주 중 자세 알림, 마이크 없이 완주를 수행한다. 행동 기록 복사와 다음 참가자 초기화까지 진행한다. | 1~2시간 |

작업량 추정은 순차 진행 기준 4시간 15분~9시간 30분이다. 디자인 변경 규모, 실기에서 발견되는 오류, 배포 계정과 장비 준비 시간에 따라 달라진다.

## 인수 후 반영한 동작

- 12마디 곡 연습은 마이크 없이도 연습 시간과 완주를 저장한다. 점수·정확도는 미측정으로 남기고 최고 점수는 유지한다.
- 8마디 전환 연습은 마이크를 사용할 수 없으면 명세대로 모의 판정하며 화면과 저장 기록에 그 방식을 표시한다.
- 출석 이후 홈에서의 학습 안내, 코스 이어하기 단축, 코스 완료 후 재연주 안내는 Figma 개발 전달 10절의 미반영 제안이다. MY의 곡 바로가기는 평가 과제에서 사용한다.

## 11월 12일 실행 기록

- 기존 전체 QA 첫 실행은 139개 통과, 1개 실패였다. 카메라 거부 안내 검사에서 고정 0.8초 대기를 화면 표시 대기(최대 8초)로 변경했다. 수정 빌드로 재실행한 결과 140개 통과, 0개 실패였다.

- 12마디 곡 연습에서 ✕ 확인창을 띄운 상태로 곡 종료 시점까지 기다리면 자동 완주가 저장되는 문제를 브라우저에서 재현했다. 확인창을 열면 타이머와 소리 감지를 멈추도록 수정했다. 확인 중 자동 완주 방지, 계속하기 후 완주, 마이크 거부 및 진행자 판정 경로를 Edge에서 재검증했다.
- 프로덕션 빌드 성공. 자동 검사는 로컬 브라우저에서 실행하며 실제 기기 소리 인식과 배포 주소 점검은 4~5단계에서 수행한다.
- 360×640 브라우저에서 참가자 P1과 P2의 수동 출석, 새로고침 뒤 당일 출석 유지, 초기화, 평가 패널의 기록 내보내기를 확인했다. 두 출석 이벤트에 해당 참가자 번호가 각각 남았다.
- 360×640과 390×844에서 12마디 곡 리포트 가로 넘침 여부, 하단 완료 버튼, 8마디 연습 진입과 결과 표시를 검사했다.
- 배포용 산출물은 앱 폴더의 `dist/`이다. 현재 체크아웃에 Git 원격과 연결된 Vercel 프로젝트가 없다. 평가 서버 연결과 통기타 리허설은 남아 있다.

### 개발 전달 10절과 재방문 동선 대조

390×844 Edge에서 당일 수동 출석, 중단한 파트, 코스 전체 완료 상태를 각각 준비해 확인했다. 아래 탭 수는 앱 홈 또는 코스 목록이 이미 열린 시점부터 센 값이다.

| 상황 | 현재 동작 | Figma 미반영 제안 |
|---|---|---|
| 출석 당일 재접속 | 홈의 ‘출석완료’는 비활성이다. 하단 ‘학습’을 1회 누르면 코스 목록이 열린다. | ‘이어서 연습하기’ 링크 또는 홈 말풍선 안내 |
| 중단한 레슨 이어하기 | 홈에서 학습 → 코스 이어하기 → 표시된 Em 레슨 → 표시된 파트까지 4회. 코스 목록부터는 3회. 파트 1의 저장된 두 번째 단계로 돌아간 것을 행동 기록에서 확인했다. | 코스 이어하기를 누르면 다음 레슨의 파트 선택창 열기 |
| 코스 완료 후 재연주 | 코스 목록에 ‘코스 1 · 완료’가 보이고, 재연주 안내는 상세에 있다. 기본 복습 탭 상태에서 연습 → 곡 연습 → 연주하기 3회로 12마디 화면이 열린다. | 코스 목록 카드에 재연주 안내 또는 버튼 추가 |

### 홈 이어하기 반영

사용자 확인 후 출석 완료 아래 ‘이어서 연습하기 ›’를 추가했다. 저장된 파트는 해당 단계로, 저장된 파트가 없으면 코스 목록으로 이동한다. 360×640 Edge에서 두 이동 경로, 버튼이 화면 안에 표시되는지, 출석 전에는 링크가 없는지 확인했다. 세 경우 모두 통과했고 프로덕션 빌드도 성공했다.

### 코스 목록 바로가기 반영

‘코스 이어하기’는 저장된 레슨을 우선하고, 없으면 잠기지 않은 첫 미완료 레슨의 파트 선택창을 연다. 전체 완료 시 ‘곡 다시 치기’로 12마디 화면을 열고 ‘코스 살펴보기’로 완료한 레슨 목록을 열 수 있다. 360×640 Edge에서 처음 시작(Em), G 레슨 중단 후 재개, Em 완료 후 다음 G 레슨, 전체 완료 후 재연주와 상세 조회의 네 시나리오가 통과했다. 프로덕션 빌드도 성공했다. 전체 140개 QA는 앞선 빌드의 결과이며 이번 변경 후에는 해당 네 경로를 집중 검증했다.

### 연습 화면 예외 묶음

- 8마디 연습의 나가기 확인창을 열면 타이머와 소리 감지를 멈춘다. 확인창을 닫고 계속하면 완료한 마디와 판정이 이어진다.
- 마이크 요청이 겹치면 진행 중인 요청을 함께 기다린다. 연습 화면을 벗어나면 마이크를 끄고, 취소 뒤 도착한 스트림도 종료한다.
- Edge에서 요청 중복 및 취소, 8마디 진행 정지 및 재개, 곡 리포트 → 전환 연습 → 원래 리포트 왕복 시 결과 보존을 확인했다. 기존 마이크 거부 회귀 경로도 통과했다.
- 전체 QA 후반부가 자동으로 열린 파트 선택창과 평가 패널을 연속으로 조작하다 클릭 대기로 중단됐다. 선택창을 닫고 평가 패널을 여는 순서로 검사를 수정하고 현재 코스 흐름 구간 C를 재실행해 54개 통과, 0개 실패를 확인했다. 참가자 교체 및 기록 복사 검사도 앱 로딩 완료 대기를 추가한 뒤 통과했다.
- 이번 빌드와 집중 회귀 검사, 코스 흐름 C가 통과했다. 실제 폰의 권한 표시와 기타 소리 기준 조정은 HTTPS 배포 후 리허설에서 확인한다.

### 모바일 점검과 배포 준비

- 320×568, 360×640, 390×844에서 홈·코스·곡 연습·미측정 리포트의 가로 넘침과 리포트 완료 버튼을 점검했다.
- 320px 미측정 리포트의 정확도 표시가 세 줄로 갈라지는 것을 이미지로 확인하고, 미측정 값의 글자 크기를 줄여 한 줄로 표시했다.
- HTML이 참조한 파일, 설치 아이콘, 자세 모델 파일이 빌드에 포함됐는지 확인했다. `vercel.json`에 Vite 빌드 명령과 출력 경로를 명시했다.
- 사용자가 새 GitHub 저장소와 Vercel 프로젝트 생성을 선택했다. 현재 계정 연동이 없어 GitHub·Vercel 플러그인 연결을 요청했다. 원격 저장소와 공개 평가 주소는 아직 생성 전이다.

### HTTPS 배포 완료

- Vercel 계정 soodalmenro의 HCI 팀(hci24)에 dinga-app 프로젝트를 생성하고 앱 폴더를 연결했다.
- [평가용 배포 주소](https://dinga-app.vercel.app/)와 [배포 관리 화면](https://vercel.com/hci24/dinga-app)을 확인했다. 운영 배포가 READY 상태이며 로그인 없는 HTTP 요청이 200과 딩가 HTML을 반환했다.
- 실제 HTTPS 주소에서 390×844 Edge로 수동 출석 → 12마디 곡 연습 → 미측정 리포트 저장 → MY 복귀를 검사했다. 테스트 브라우저에서 권한 거부와 빠른 타이머를 사용했으며 화면 오류가 없었다.
- GitHub CLI 설치를 완료했다. 저장소 생성 및 Git 연동은 GitHub CLI 인증 승인을 기다린다. 실제 폰에서 마이크·카메라 사용과 통기타 기준값 확인은 남아 있다.

### GitHub 저장소 업로드

- GitHub 계정 soodalmenro의 [dinga-app 비공개 저장소](https://github.com/soodalmenro/dinga-app)를 생성했다. 앱 폴더를 독립 저장소로 만들고 첫 커밋 0305ac3을 main에 업로드했다. 원격 커밋 해시 일치도 확인했다.
- 환경 파일, Vercel 로컬 연결 설정, node_modules 및 빌드 출력은 Git에서 제외된다.
- Vercel git connect는 저장소 접근 오류로 실패했다. Vercel GitHub 앱에 해당 비공개 저장소의 접근 허용이 필요하다. 기존 HTTPS 배포는 정상 제공 중이며 자동 배포 연결은 남아 있다.

### 자동 배포 연결

GitHub 접근 승인 후 Vercel의 hci24/dinga-app에 soodalmenro/dinga-app 저장소 연결을 완료했다. 이 기록을 main에 올려 Git 기반 자동 배포가 생성되고 완료되는지 확인한다.
