# 코드 판정 신뢰성 보강

2026-11-12. 사용자 요청에 따라 ‘불명확한 소리의 강제 판정 방지’와 ‘같은 입력을 반복하는 검증 환경’을 개발했다. 실제 기타 실기는 마지막에 진행한다.

## 사용자에게 달라지는 동작

- 마이크에서 소리는 들렸지만 음 구성이 불명확하면 ‘판정 어려움’을 표시한다. 정답 체크나 코드 오답으로 표시하지 않는다.
- 박자는 별도로 측정한다. 코드 판정이 어려운 마디가 있어도 측정한 박자 정확도는 보여 준다.
- 코드 판정 보류가 한 마디라도 있으면 해당 시도의 코드 정확도·종합 점수는 보류하며 최고 기록을 갱신하지 않는다. 일부 명확한 마디만 골라 높은 종합 점수를 내지 않는다.
- 완주·레슨 진도·연습 시간은 정상 기록한다. 마이크 미사용의 ‘측정 안 됨’과 판정 보류는 구분한다.
- 리포트에 연주한 마디 수, 코드를 평가한 마디 수, 판정이 어려운 마디 수를 표시한다. 무음 마디는 소리 미감지 실패로 평가하므로 ‘코드 평가’ 개수에 포함한다.
- 미확정 전환은 성공률의 분모에서 제외하고 보류 횟수를 따로 표시한다. 보류만 있는 전환을 오답·늦음으로 추천하지 않는다.
- 이전 버전 리포트는 새 측정 범위가 없더라도 그대로 읽는다. 새 측정 범위나 전환 수치가 손상된 리포트는 안전하게 무효 처리한다.

## 판정 규칙

독립 함수 `src/chordRecognition.js`의 버전은 `chroma-guard-v1`이다. 다음 조건을 모두 만족하는 경우에만 Em·G·C 후보를 확정한다.

| 항목 | 현재 공학적 기준 |
|---|---|
| 후보 코드 구성음 에너지 비중 | 0.85 이상 |
| 1위와 2위 후보의 비중 차이 | 0.12 이상 |
| 후보의 각 구성음 에너지 비중 | 각각 0.08 이상 |
| 입력 검증 | 12개 유한한 음수 아닌 값. 무음·잘못된 입력은 판정 안 함 |

비중과 차이는 정확도나 확률이 아니다. 합성 입력에서 모호함을 거르는 임시 기준이며, 실제 기타 자료로 정밀도·재현율을 측정한 값이 아니다. 마이크의 소리 크기 감지 기준 0.05는 이번에 변경하지 않았다.

소리 분석의 FFT 크기를 8192에서 16384로 보강했다. 기존 설정에서 48kHz 합성 Em 3화음이 약 0.818의 구성음 비중으로 보류되는 문제가 재현됐으며, 새 설정에서는 약 0.992였다. 48kHz 기준 주파수 간격은 약 5.86Hz에서 2.93Hz로 작아진다. 분석 구간은 약 171ms에서 341ms로 길어진다. 시간영역 소리 시작 감지기(1024)는 유지한다.

## 반복 검증 도구

| 도구 | 검증 범위 |
|---|---|
| `node qa/chord-replay.cjs` | 고정 합성 벡터 18개, 잘못된 입력과 볼륨 배율. 기존 강제 판정과 새 결과를 나란히 출력 |
| `node qa/chord-summary.cjs` | 미확정·혼합·오답·무음·마이크 없음·일부 연주·빈 시도의 점수와 구간 결과 |
| `node qa/chord-audio.cjs` | 합성 정현파 → MediaStream → 앱 FFT → 판정, 44.1kHz·48kHz 총 20개 |
| `node qa/chord-browser.cjs` | 보류 표시, 박자·완주·최고 기록 정책, 새 저장값 손상 처리, 이전 형식, 재로드 및 320·360·390px 리포트 |

브라우저 도구에는 Playwright가 필요하다. Edge에서는 `QA_BROWSER_CHANNEL=msedge`를 사용한다. 벡터·요약 검사는 Vite의 SSR 로더를 사용하며 브라우저 없이 실행한다. 오디오 검사는 합성 스트림을 사용하며 마이크나 스피커에서 실제 음원을 수집·재생하지 않는다.

새 리포트에는 마디별 판정 이유·검출 코드·판정 버전과 측정 범위가 저장된다. 원음·영상·주파수 배열은 저장하지 않는다. 데이터는 기존과 같이 해당 브라우저에만 남는다.

최종 검증에서 합성 벡터 18개와 잘못된 입력·배율·타입 제어, 합성 오디오 20개, 7종 요약 시나리오, 보류 브라우저·저장·모바일 검사, 기존 전체 QA 140개가 통과했다. 기존 품질 검사 10개·모바일 화면 12개 조합·저장 복구 검사도 통과했다. 일반·단일 파일 빌드는 성공했으며 런타임 의존성 감사는 0건이다. 별도 읽기 전용 재검토에서 확정된 회귀는 없었다.

## 검증 범위의 한계

- 합성 벡터의 기대 결과는 공학적 계약이다. 실제 기타 인식률이나 사용자 성공률로 해석하지 않는다.
- 합성 오디오 검사는 600ms 후 지속 정현파를 평가한다. 실제 줄의 감쇠, 배음, 튜닝 오차, 손가락 소음과 짧은 어택을 검증하지 않는다.
- 늘어난 분석 구간과 계산량이 코드 전환 과도상태, 저성능 휴대폰, 발열과 처리 지연에 미치는 영향은 실기로 확인해야 한다.
- 보수적인 기준 때문에 올바르게 친 기타도 보류될 수 있다. 실제 기타에서 조건별 오답·보류·정답을 수집한 후 기준을 보정한다.
- 카메라 촬영 조건 안내와 마이크 입력 준비 단계는 후속 개발한 [연습 환경 확인](PRACTICE_ENVIRONMENT.md)에서 별도로 설명한다. 코드 분류 기준과 입력 크기 기준은 서로 다른 역할이다.
