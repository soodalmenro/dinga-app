# 11/18 수정 (수민 · main 6888567 기준)

## 1. 코드 변형도 정답으로 인정

Chordino는 같은 코드를 `Em7`, `Em/B`, `E5`처럼 변형 이름으로 읽기도 한다. 지금까지는 `Em`, `G`, `C` 글자와 정확히 같아야만 세서, 실제 기타·유튜브 소리에서 한 번도 통과하지 못했을 가능성이 크다.

- 새 파일 `src/chordMatch.js`: 근음이 같고 3음(장조/단조)이 반대가 아니면 같은 코드로 본다.
  - Em 목표: Em, Em7, Em6, Em9, Em/B, E5, Esus4 인정 · E, E7(장조)은 다른 코드
  - G 목표: G, G6, G7, Gmaj7, Gadd9, G/B, G5 인정 · Gm은 다른 코드
  - C 목표: C, C6, Cadd9, C/E 인정 · Cm은 다른 코드
  - dim·aug·m7b5는 어떤 목표에도 인정하지 않는다
- `guitarEar.js`는 받은 코드 이름을 이 묶음으로 바꿔 저장한다(Em7↔Em가 번갈아 읽혀도 코드 유지 시간이 끊기지 않게).
- `guitarHitGate.js`(레슨 횟수·박자·8마디), `SongPlay.jsx`(12마디 채점)가 같은 비교를 쓴다.
- 타자·말소리·무음으로는 여전히 통과하지 않는다(코드가 350ms 이상 안정돼야 함).

문구: 출석 제목 "아는 코드를 쳐 주세요!", 설명 "Em·G·C처럼 익숙한 코드면 돼요. 코드 소리가 2초 들리면 출석이에요." 인식 상태는 "Em 코드가 들려요" / "지금은 G 코드가 들려요 · Em 코드를 쳐 주세요" / "Em 코드를 쳐 주세요". 11/18 새벽에 되돌아간 문구("코드가 확인된 입력만 세어요" 등)와 8마디 결과의 "– 코드 확인 안 됨"도 다시 고쳤다.

## 2. 자세 알림 카메라 창을 캐릭터 자리로

피그마 P1(11/16): 알림 3초 동안 카메라 창 + 교정 그림. 오른쪽 위 작은 창이 코드 그림을 가리고 "떴다 사라지는" 것처럼 보여서, 레슨 연주 단계(소리 내기·박자·안 보고 치기·전환)에서는 캐릭터가 있던 자리에 크게 보여 준다. 3초가 지나면 캐릭터가 돌아온다. 곡 연습 화면은 캐릭터 자리가 없어 화면 가운데에 겹쳐 보여 준다. 곡 연습 알림 문구도 피그마와 같게 "손목이 꺾였어요 / 살짝 펴 볼까요?"로 맞췄다.

## 3. 자세 촬영(S7) 사진을 실제로 판정

조교 피드백(10/26)의 "범위를 사진 한 장 점검으로 좁히기"와 피그마 14·15 가이드 선, 「통기타를 연주하는 바른 자세」(어쿠스틱 체이서) 글을 기준으로 했다.

- 새 파일 `src/postureCheck.js`: MediaPipe Tasks Vision(Apache-2.0)의 몸 관절 33점 + 손 관절 21점을 폰 안에서 계산한다. 모델·wasm은 `public/vision/`(약 28MB, 자세 촬영 때 처음 불러옴). 사진과 좌표는 저장·전송하지 않는다.
- 판정 항목(결과 화면 4줄, 이번 레슨의 중심 항목이 맨 위):

| 항목 | 기준 | 근거 |
|---|---|---|
| 손목 | 팔뚝(팔꿈치→손목)과 손(손목→중지 뿌리) 각도가 30도(`poseThresholds.photoWristDeg`) 넘으면 주의 | 글: 왼손이 낮으면 손목을 많이 꺾게 됨. RULA는 굴곡·신전 15도부터 위험 점수, 기타 해부학 교본은 왼손목 굴곡 10~20도 이내 권장. 정면 사진 오차를 감안해 30도 |
| 왼손 높이 | 코드 잡는 손목이 소리 내는 손목보다 아래(사진 높이 2% 넘게)면 주의 | 글: 왼손은 사운드홀보다 약간 높게 / 피그마 "왼손은 이 선보다 위" |
| 어깨 | 어깨선 기울기 12도 초과, 또는 한쪽 귀~어깨 거리가 너무 짧거나 반대쪽의 70% 미만이면 주의 | 글: 왼손이 낮으면 오른 어깨가 올라감 / 피그마 "양쪽 높이를 같게" |
| 엄지 | 항상 "확인 어려움" | 넥 뒤에 가려져 카메라로 보지 않음(PRD도 엄지 판정 제외) |

- 손·팔이 가려지거나 화면 밖이면 "괜찮음"을 지어내지 않고 "확인 어려움"으로 보여 준다. 결과 사진 위에 실제로 찾은 어깨선·팔·손 선을 부위별 색(초록 괜찮음 / 주황 주의 / 회색 확인 어려움)으로 그린다.
- 평가 패널 "자세 촬영 결과": 사진으로 실제 판정(기본) / 시뮬레이션 / 참가자가 직접 선택.
- 연주 중 알림(P1)은 그대로 정해진 시점(5초 뒤 한 번)이다. 실시간 판정이 아니다.

**참고 자료**: 어쿠스틱 체이서 「통기타를 연주하는 바른 자세」(https://acousticchaser.tistory.com/151), RULA 가이드(https://ergo-plus.com/wp-content/uploads/9-RULA-Companion-Guide.pdf), 기타 해부학 교본 샘플(https://boileau-music.com/uploads/imgen/14460_L-LSDGI_muestra_sample.pdf), 기타 연주자 통증 연구 PLOS ONE 2022(https://pmc.ncbi.nlm.nih.gov/articles/PMC8726467, 코드 잡는 손목이 통증 1위), 웹캠 관절 각도 한계(https://arxiv.org/pdf/2310.07322). 어깨 비대칭과 통기타 넥 각도는 수치 기준을 찾지 못해 참고값으로 둔다. MediaPipe로 기타 자세를 판정한 공개 오픈소스는 찾지 못했다.

**한계**: 정면 사진 한 장이라 깊이 방향으로 꺾인 손목은 덜 보인다. 기준값은 실제 기타로 맞추기 전의 시작값이다. 자동 검사는 사람이 없는 가짜 카메라 영상으로 모델이 돌고 "확인 어려움"이 나오는 것, 그리고 좌표를 넣은 규칙 검사까지만 확인했다. 실제 사람·기타 사진의 정확도는 폰으로 찍어 봐야 안다.

## 8. QA 반영 (11/18 15:47 기준 수정 건)

**공통**
- 미니카메라 삭제: 연주 중 자세 알림은 문구 + 진동만(레슨·곡 연습). 카메라는 자세 촬영(S7)과 패널의 "실제 판정" 모드에서만 켠다. PRD 문서의 미니카메라 문장 3곳은 제안 모드로 고쳐 두었다.
- 나갔다 들어오면 처음부터: 새로 설치한 기기는 기본으로 새로고침하면 처음 상태로 돌아간다(평가 패널 "새로고침하면 처음부터", 주소 끝 `?fresh=1` 켬 / `?fresh=0` 끔). 이미 쓰던 기기는 패널에서 켜야 한다.
- 안내 문구(~하세요, 준비 3·2·1, 코드 인식 결과)를 캐릭터 말풍선으로. "Em 코드를 쳐 주세요", "코드 인식 다시 시도" 같은 작은 문장·버튼은 지웠다(진단 표시를 켜면 기존처럼 보임).

**출석**: 소리를 못 들으면 버튼 없이 다시 듣고, 말풍선에 "다시 소리 내 주세요!".

**자세 확인(S7)**: 촬영 화면의 기타 윤곽 가이드 삭제. 결과는 손목·어깨·엄지 3줄이고 줄마다 괜찮음/주의 중 하나가 늘 체크된다. 사진으로 못 본 곳(엄지 등)은 괜찮음으로 미리 골라 두고 참가자가 바꿀 수 있다. 왼손 높이 주의는 손목 줄에 합쳤다. 기록에는 실제로 잰 곳(`measured`)을 남긴다.

**레슨 구성**
- 파트 1 "준비": 기타 안기 카드 → 자세 촬영 → 코드 잡기(카드·그림) → 소리 내기. 코드 잡기를 촬영 뒤로 옮겼다.
- 파트 2 "코드 연습": 소리 내기(+ G·C는 코드 전환). 파트 3 "박자 연습": 안 보고 치기 → 박자(BPM).
- 명령은 "Em 코드를 4번 쳐 주세요"(G·C 동일), 들리면 말풍선 "Em 코드 소리가 들려요!".
- 박자: 50 → 60으로 넘어갈 때 "이번엔 조금 더 빨라져요!", 박자를 놓치면 째려보는 얼굴, 50·60 모두 메트로놈 소리.

**친구와 같은 곡 연습**: 곡을 The Itsy Bitsy Spider(G·C·Em만, 12마디)로 바꾸고 멜로디를 같이 재생(화면의 "멜로디 켬/끔"). 연주를 시작하기 전까지 메트로놈을 박자마다 반복한다.

**주의**: 멜로디·메트로놈 소리를 마이크가 기타로 들을 수 있다. 이어폰을 권한다. 마이크 판정이 아닌 모드에서는 대기 중 메트로놈 소리로 시작될 수 있다.

**검사**: `qa/qa.cjs` 148개 통과. 단계 순서·문구·카메라가 바뀐 검사 15개(`guitar-app-browser`, `posture-photo-browser`, `evaluation-*`, `camera-delayed-permission`, `progress-checkpoint`, `setting-integrity`, `resume-variant`, `course-modal`, `pose-reliability`, `media-recovery`, `repeated-use`, `guitar-failure-browser`, `input-diagnostics-browser`, `participant-handoff`)를 새 흐름에 맞췄다.

## 8-2. QA 반영 추가 (같은 날)

- 말풍선 줄바꿈을 단어 단위로(`word-break: keep-all`, 두 줄이면 길이를 고르게). "준비하고 있 / 어요"처럼 글자 중간에서 끊기지 않는다.
- 운지법(diagram)을 한 화면에: 손가락 번호가 모두 그려진 코드 그림 + 손가락별 설명 + "다음" 버튼 하나. 손가락마다 "올렸어요"를 누르던 단계를 없앴다.
- 곡 연습 멜로디가 안 들리던 문제: 인트로 4마디가 비어 있었고(→ 1절 첫 4마디 멜로디를 미리 들려 줌, 코드가 G Em C G로 같다), 음량이 작았고(0.07 → 최고 0.32, 한 옥타브 위 사인파를 섞어 폰 스피커에서도 들리게), 폰은 터치 없이 만든 오디오가 잠겨 있을 수 있어 첫 터치 때 오디오를 깨운다.
- 자세 촬영(S7) 카메라 위 가이드(점선 윤곽·고정 선·사운드홀 점선·태그·안내 문구)를 지웠다. 위의 "바른 자세 (참고)" 사진과 결과 화면의 선·태그는 그대로다.
- 출석 화면 위 제목("아는 코드를 쳐 주세요!")을 빼고 캐릭터 말풍선 하나로 안내한다(QA "~하세요는 말풍선", 피그마 02와 같게). 마이크를 못 쓸 때만 제목을 둔다.
- 연습 탭 곡 연습(Itsy Bitsy Spider)을 코스 완주 전에도 연다. "코스 1의 완주하기를 마치면 열려요", "끝낸 코스의 곡을 다시 연주해요" 문구를 지웠다.
- 앱 전체 줄바꿈을 단어 단위로(`word-break: keep-all`, 제목·말풍선·안내는 줄 길이를 고르게). 화면이 낮을 때 말풍선이 위의 점·카드를 덮지 않게 했다(대신 화면이 스크롤).

## 9. 실패하던 검사 정리 (11/19)

계속 실패하던 검사 5개를 확인했다. 모두 앱 문제가 아니라 검사가 예전 앱 기준이었다.

- `embedded-progress`: 파트 중간으로 들어가면 먼저 나오는 자세 촬영(S7)을 몰랐고, 레슨 안 전환 연습의 [시작하기]를 찾았다(지금은 3·2·1 뒤 저절로 시작). 마이크 끊김 부분은 소리 크기로 세는 모의 판정으로.
- `evaluation-pause` 출석: 소리 크기로 출석을 채우려 했다(출석은 코드 인식으로 센다). 코드가 들리는 상태를 흉내 내어 "패널을 열면 출석이 멈추는지"를 그대로 확인한다.
- `quality-review`: 소리 크기·옛 화음 흉내로 마이크 판정을 흉내 냈다. 늦은 마이크 허락·부분 연습 최고 점수는 모의 판정으로, "마이크로 끝까지 치면 최고 점수 갱신"은 실제 기타 소리 검사(`guitar-app-browser` 12마디)로 옮겼다.
- `media-recovery` 전환 부분: 같은 이유로 모의 판정(random)으로 끊김 복구를 본다.
- `input-diagnostics-browser`: 검사가 만든 가짜 Em이 늘 같은 크기로 울려 코드 인식이 B5·Ab°로 읽었다. 실제 기타처럼 1초마다 치고 줄어드는 소리로 바꿨고, 출석 대기는 20초로.

## 10. 11/19(목) 12:00 QA — 코드 전환 연습에서 다른 코드 알려주기

**다른 코드 알려주기**: 전환 연습에서 마디 코드가 아닌 다른 코드가 들리면 캐릭터가 바로 "지금은 G 코드예요. Em 코드를 쳐 주세요"라고 말한다(2.5초). 그 마디는 빨간 칸에 들린 코드(예: "G")로 표시한다. 레슨 안 전환 연습과 연습 탭 전환 연습 모두. 마이크 판정에서만 동작한다(모의 판정은 코드를 듣지 않는다).

**한 번이라도 틀리면 다시 연습**: 레슨 안 전환 연습(G·C 파트 2, 첫 곡 전환 1·2)에서 8마디 중 한 마디라도 다른 코드로 쳤으면 파트 완료 대신 "다른 코드로 친 마디가 N개 있어요. 처음부터 다시 해 볼까요?"와 [다시 연습하기]. 누르면 8마디를 처음부터(준비 3·2·1). 늦음·빠름은 지금처럼 통과. 행동 기록 `transition_end`에 `retry: true|false`. 연습 탭 전환 연습은 결과 화면에 "다른 코드" 마디로 남는다.

**판정**: 코드 판정 게이트(`guitarHitGate.js`)가 지금까지 다른 코드 소리를 조용히 버렸는데, 이제 `onMiss`로 들린 코드를 알려 준다. 박 판정과 같은 마디 구간(¼박 앞당김)으로 마디를 정한다.

**검사**: `guitar-app-browser`에 `8bar-wrong` 경우 추가(첫 G 마디에 실제 C 소리 → 말풍선·다시 연습·처음부터 다시). 맞게 친 8마디(`8bar`)는 그대로 파트 완료.
