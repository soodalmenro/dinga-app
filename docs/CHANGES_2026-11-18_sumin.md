# 11/18 수정 (수민 · main 6888567 기준)

## 1. 코드 변형도 정답으로 인정

Chordino는 같은 코드를 `Em7`, `Em/B`, `E5`처럼 변형 이름으로 읽기도 한다. 지금까지는 `Em`, `G`, `C` 글자와 정확히 같아야만 세서, 실제 기타·유튜브 소리에서 한 번도 통과하지 못했을 가능성이 크다.

- 새 파일 `src/chordMatch.js`: 근음이 같고 3음(장조/단조)이 반대가 아니면 같은 코드로 본다.
  - Em 목표: Em, Em7, Em6, Em9, Em/B, E5, Esus4 인정 · E, E7(장조)은 다른 코드
  - G 목표: G, G6, G7, Gmaj7, Gadd9, G/B, G5 인정 · Gm은 다른 코드
  - C 목표: C, C6, Cadd9, C/E 인정 · Cm은 다른 코드
  - dim·aug·m7b5는 어떤 목표에도 인정하지 않는다
- `guitarEar.js`는 받은 코드 이름을 이 묶음으로 바꿔 저장한다(Em7↔Em가 번갈아 읽혀도 코드 유지 시간이 끊기지 않게).
- `guitarHitGate.js`(레슨 횟수·박자·8마디), `SongPlay.jsx`(12마디 채점)가 같은 비교를 쓴다.
- 타자·말소리·무음으로는 여전히 통과하지 않는다(코드가 350ms 이상 안정돼야 함).

문구: 출석 제목 "아는 코드를 쳐 주세요!", 설명 "Em·G·C처럼 익숙한 코드면 돼요. 코드 소리가 2초 들리면 출석이에요." 인식 상태는 "Em 코드가 들려요" / "지금은 G 코드가 들려요 · Em 코드를 쳐 주세요" / "Em 코드를 쳐 주세요". 11/18 새벽에 되돌아간 문구("코드가 확인된 입력만 세어요" 등)와 8마디 결과의 "– 코드 확인 안 됨"도 다시 고쳤다.

## 2. 자세 알림 카메라 창을 캐릭터 자리로

피그마 P1(11/16): 알림 3초 동안 카메라 창 + 교정 그림. 오른쪽 위 작은 창이 코드 그림을 가리고 "떴다 사라지는" 것처럼 보여서, 레슨 연주 단계(소리 내기·박자·안 보고 치기·전환)에서는 캐릭터가 있던 자리에 크게 보여 준다. 3초가 지나면 캐릭터가 돌아온다. 곡 연습 화면은 캐릭터 자리가 없어 화면 가운데에 겹쳐 보여 준다. 곡 연습 알림 문구도 피그마와 같게 "손목이 꺾였어요 / 살짝 펴 볼까요?"로 맞췄다.

## 3. 자세 촬영(S7) 사진을 실제로 판정

조교 피드백(10/26)의 "범위를 사진 한 장 점검으로 좁히기"와 피그마 14·15 가이드 선, 「통기타를 연주하는 바른 자세」(어쿠스틱 체이서) 글을 기준으로 했다.

- 새 파일 `src/postureCheck.js`: MediaPipe Tasks Vision(Apache-2.0)의 몸 관절 33점 + 손 관절 21점을 폰 안에서 계산한다. 모델·wasm은 `public/vision/`(약 28MB, 자세 촬영 때 처음 불러옴). 사진과 좌표는 저장·전송하지 않는다.
- 판정 항목(결과 화면 4줄, 이번 레슨의 중심 항목이 맨 위):

| 항목 | 기준 | 근거 |
|---|---|---|
| 손목 | 팔뚝(팔꿈치→손목)과 손(손목→중지 뿌리) 각도가 30도(`poseThresholds.photoWristDeg`) 넘으면 주의 | 글: 왼손이 낮으면 손목을 많이 꺾게 됨. RULA는 굴곡·신전 15도부터 위험 점수, 기타 해부학 교본은 왼손목 굴곡 10~20도 이내 권장. 정면 사진 오차를 감안해 30도 |
| 왼손 높이 | 코드 잡는 손목이 소리 내는 손목보다 아래(사진 높이 2% 넘게)면 주의 | 글: 왼손은 사운드홀보다 약간 높게 / 피그마 "왼손은 이 선보다 위" |
| 어깨 | 어깨선 기울기 12도 초과, 또는 한쪽 귀~어깨 거리가 너무 짧거나 반대쪽의 70% 미만이면 주의 | 글: 왼손이 낮으면 오른 어깨가 올라감 / 피그마 "양쪽 높이를 같게" |
| 엄지 | 항상 "확인 어려움" | 넥 뒤에 가려져 카메라로 보지 않음(PRD도 엄지 판정 제외) |

- 손·팔이 가려지거나 화면 밖이면 "괜찮음"을 지어내지 않고 "확인 어려움"으로 보여 준다. 결과 사진 위에 실제로 찾은 어깨선·팔·손 선을 부위별 색(초록 괜찮음 / 주황 주의 / 회색 확인 어려움)으로 그린다.
- 평가 패널 "자세 촬영 결과": 사진으로 실제 판정(기본) / 시뮬레이션 / 참가자가 직접 선택.
- 연주 중 알림(P1)은 그대로 정해진 시점(5초 뒤 한 번)이다. 실시간 판정이 아니다.

**참고 자료**: 어쿠스틱 체이서 「통기타를 연주하는 바른 자세」(https://acousticchaser.tistory.com/151), RULA 가이드(https://ergo-plus.com/wp-content/uploads/9-RULA-Companion-Guide.pdf), 기타 해부학 교본 샘플(https://boileau-music.com/uploads/imgen/14460_L-LSDGI_muestra_sample.pdf), 기타 연주자 통증 연구 PLOS ONE 2022(https://pmc.ncbi.nlm.nih.gov/articles/PMC8726467, 코드 잡는 손목이 통증 1위), 웹캠 관절 각도 한계(https://arxiv.org/pdf/2310.07322). 어깨 비대칭과 통기타 넥 각도는 수치 기준을 찾지 못해 참고값으로 둔다. MediaPipe로 기타 자세를 판정한 공개 오픈소스는 찾지 못했다.

**한계**: 정면 사진 한 장이라 깊이 방향으로 꺾인 손목은 덜 보인다. 기준값은 실제 기타로 맞추기 전의 시작값이다. 자동 검사는 사람이 없는 가짜 카메라 영상으로 모델이 돌고 "확인 어려움"이 나오는 것, 그리고 좌표를 넣은 규칙 검사까지만 확인했다. 실제 사람·기타 사진의 정확도는 폰으로 찍어 봐야 안다.

## 5. 두 번째 반영 (같은 날)

- 수아의 `feature/pose-judgment-debug`(3D 손목 각도, 기준 자세, 디버그 화면)를 합쳤다. 실제 판정 모드·패널에서만 동작한다. 합치면서 0.4초 정도 관절이 안 보였다가 돌아오면 자세 지속 시간이 이어지던 문제를 고쳤다(`pose.js`: 그 부위를 못 재면 바로 초기화).
- 출석·레슨의 "마이크 입력" 막대와 "입력 진단 정보"는 평가 패널 "마이크 입력 진단 표시"를 켤 때만 보인다(기본 꺼짐).
- 패널 "파트 3 카메라 테스트"는 곡 판정 설정을 바꾸지 않는다(전에는 '모두 성공'으로 바꾼 채 남았다).
- MY 친구와 같은 곡 연습 카드에 "같은 코스 친구들과 같은 곡을 쳐요"를 넣었다.
