# 품질 재검토 — 2026-11-12

## 현재 평가

화면 흐름을 실행할 수 있는 연구용 프로토타입이다. 실제 기타의 코드·박자 인식 정확도와 기타에 가려진 손목의 인식률을 검증한 제품은 아니다. 이전의 정상 경로 중심 자동 검사는 아래의 권한·중단·재시도 오류를 놓쳤다. 자동 검사 통과와 실기 정확도를 구분해서 전달해야 한다.

## 동작 변경과 기록 해석

- 곡 연습 메트로놈은 기본 끔이다. 사용자가 켤 수 있으며 마이크가 켜져 있으면 이어폰 안내를 표시한다. 스피커 클릭음이 연주로 감지되는 위험을 줄이기 위한 설정이며, 실제 기기의 피드백 제거 성능을 측정한 결과는 아니다.
- 마이크 없는 12마디 완주는 점수 없이 완료와 시간을 남긴다. 8마디의 모의 판정은 개발 전달 명세에 따른 기존 정책을 유지한다.
- 모의 판정·중도 종료는 앞으로 최고 기록을 갱신하지 않는다. 이전 버전의 최고 기록은 출처가 없어 실제·모의를 소급 구분할 수 없으므로 삭제하지 않는다.
- 기본 자세 알림은 여전히 정해진 시점에 표시하는 시뮬레이션이다. 실제 자세 판정으로 임의 전환하지 않았다.
- 파트 완료 180초·독립 전환 120초 기록은 기획의 명목 시간 규칙이다. 이번 변경은 중도 종료 시 팝업과 숨김 시간을 제외하는 데 적용한다.

## 검증 근거

`qa/quality-review.cjs`는 Edge 브라우저와 가짜 미디어 장치를 사용해 다음 10개 사례를 확인한다.

1. 권한 무응답 상태에서 수동 출석 후 늦은 허용 응답
2. 연주 복귀 후 늦은 마이크 허용과 네 번의 소리 감지
3. 부모 나가기 팝업 중 내장 전환 연습 정지·재개
4. 최종 레슨 재시도 후 완료 진도와 모의 점수 구분
5. 실제 판정의 부분 100점 최고 기록 제외, 코드·박자 요약 분리
6. 마이크 판정 경로로 완주한 유효 점수의 최고 기록 갱신
7. 백그라운드 전환 후 마디 보존·명시적 재개
8. 팝업 제목·초기 포커스·Tab 순환·Escape

10. 촬영 카운트 정지·재개와 재촬영 라이브 미리보기

추가로 기존 중단·리포트 왕복, 저장 실패 복구, 자세 모델 실패·시간 초과·자원 해제, 무마이크·모의 판정, 운지·콘텐츠·현재 마디 스크롤, 320·360·390px 화면 검사를 수행한다. 가짜 입력의 성공은 실제 기타 인식률을 의미하지 않는다. 별도 읽기 전용 코드 재검토에서도 수정 후 추가로 확정된 회귀는 없었다.

전체 검사 첫 실행에서는 139개 통과, 카메라 미리보기 검사 1개 실패가 나왔다. 고정 900ms 대기 후 스트림만 확인하던 검사를 실제 영상 프레임 준비(readyState·videoWidth)까지 기다리는 검사로 보강했다. 별도 재촬영 검사는 실제 프레임과 살아 있는 스트림을 확인한다.

최종 Vite 6.4.6 빌드에서 전체 140개와 추가 품질 검사 10개가 모두 통과했다. 일반·단일 파일 빌드도 성공했으며 의존성 감사는 0건이다. 모바일 12개 조합과 기존 예외·저장·자세·콘텐츠 검사는 이 변경 묶음의 검증 과정에서 통과했다.

## 11/13 추가 보강: 평가 패널 뒤의 실행 중단

평가 패널은 앱 위에 표시되지만 기존에는 연습 화면에 패널 표시 상태가 전달되지 않았다. 실제 브라우저에서 패널을 연 채 기다리면12마디·8마디 진도가 늘고, PRD 촬영 카운트가 끝나며, 출석 소리가 누적되고, 환경 측정이 계속되는5개 경로를 재현했다.

- 패널 표시 상태를 출석·레슨·곡 실행에 전달해 타이머와 성공 입력을 멈춘다. 닫으면 기존 연습을 이어간다. 레슨의 중도 종료 시간에도 패널 조작 시간을 넣지 않는다.
- 출석은 패널 이전에 실제 관측한 소리 누적을 보존하고, 패널 뒤의 소리·대기 시간은 제외한다. 출석 완료 후 자동 화면 전환도 패널 중에는 멈춘다.
- 소리 출석도 완료 순간 마이크를 해제한다. 화면 전환이 지연돼도 입력 장치를 계속 점유하지 않는다.
- 환경 확인의 진행 중 측정·추적은 패널 진입 시 취소하고 직접 다시 확인해야 한다. 시작하지 않은 확인은 그대로 둔다. 취소 후 늦은 권한 응답은 기존 세대 검사로 해제한다.
- 패널의 단계 건너뛰기·자세 알림·초기화·내보내기 기능은 유지한다. 운영 중단이 진도 성공으로 집계되는 것과 진행자의 명시적 단계 변경을 구분한다.

`qa/evaluation-pause.cjs`에서 곡2종·촬영·출석·환경 확인의 정지/재개를 검사한다. 출석 누적 보존·완료 자원 해제·완료 화면 유지, 환경 확인의 미시작 상태·취소·명시적 재시작도 포함한다. 초기5개 실패와 추가2개 상태 실패를 본 뒤 수정했다. 카메라·마이크는 가상 장치이며 실제 기기 검증은 마지막으로 유지한다.

추가로 패널의 실행 속도를3→1로 바꾸면 이전 속도의 경과 시간을 새 속도로 해석해, 완료 마디는 남아 있는데 현재 마디 표시가 사라지는 오류를8·12마디 모두 재현했다. 속도 변경 시 완료 결과를 유지하고 미완료 마디를 새 속도로 다시 측정한다. 이전 마디의 입력·분석 증거는 섞지 않는다. 첫 마디를 다시 시작하는 경우에도 같은 시도의 시작 이벤트는 한 번만 남긴다.8마디에서 실제 입력을 모의 판정으로 명시적으로 바꾸는 경우는 새 시도이므로 새 시작 이벤트를 남긴다.

속도 변경2종과 첫 마디 변경2종을 포함한 총9개 패널 경로가 통과했다. 이는 평가용 가속 설정의 상태 무결성을 위한 처리이며 실제 기타 인식률을 보정하는 변경은 아니다.

## 11/14 추가 보강: 화면 구성 전환과 참가자 설정

아이디어 반영 구성은 자세 촬영 단계를 생략한다. 이전에는 PRD 원본으로 바꾸면서 이어하기의 숫자 위치를 그대로 사용해 다른 학습 단계가 열렸다. 저장된 내용을 기준으로 같은 단계로 옮기며, 대응 단계가 없거나 곡 구성이 다르면 같은 파트의 첫 단계로 돌아간다. 완료·점수·연습 시간과 저장 스키마는 바꾸지 않는다.

출석·레슨·전환·곡·환경 확인 화면에서는 참가자 번호와 화면 구성을 잠근다. 화면을 나간 뒤 바꿀 수 있으며, 다른 평가 제어와 JSON 회수는 유지한다. 참가자 번호 변경이 기존 진도를 삭제하지 않는다는 안내와 새 참가자의 수동 초기화 안내도 제공한다.

수정 전 브라우저 4개 시나리오의 실패를 확인하고 수정 후 통과했다. `qa/resume-variant.cjs`는 양방향 전체 134개 단계 대응, 촬영·곡의 보수적 복귀, 손상 위치와 입력 불변성을 검사한다. `qa/setting-integrity.cjs`의 8개 경로는 실제 화면 재개·새로고침·활성 화면 잠금·화면 밖 편집과 기록 비우기·내보내기 유지 여부를 검사한다. 별도 읽기 전용 코드 검토에서 추가로 확정된 문제는 없었다.

최종 빌드에서 전체 140개, 이어하기·이탈 10개, 패널 정지·속도 9개와 품질 10개가 통과했다. 기록 회수·참가자 전달과 빌드 결과물의 핵심 6개 흐름도 통과했다. 전체 검사의 참가자 번호 입력은 새 정책에 맞게 출석 진입 전에 수행하도록 옮겼다. 일반·단일 파일 빌드 모두 성공했다.

## 11/14 추가 보강: 저장 결과의 값 복구

저장 기록을 읽을 때 완료·코스 연습 여부를 문자열의 참/거짓으로 해석하지 않고 실제 불리언 `true`만 인정한다. 곡·전환 결과의 최초 완료 표시와 친구 챌린지도 같은 기준을 따른다. 정상 숫자처럼 보이던250점 최고 기록과 소수·안전 범위를 벗어난 완주 횟수는0으로 복구한다. 잘못된 최고 점수를100으로 잘라 완벽한 측정 기록처럼 만들지 않는다.

정상 최고 기록·리포트·완료 파트·이어하기·연습 시간은 유지한다. 최신 결과가 모의 판정이나 미완료여도 기존의 유효한 최고 점수는 지우지 않는다. 이전 버전의 누락 필드는 기존 비완료 의미에 맞춰 처리한다. 전체 초기화나 새 저장 형식은 추가하지 않는다.

수정 전에 저장 값 검사6개의 실패를 확인했고, 수정 후 정상·이전 기록·기존 최고 점수 보존을 포함한8개 검사와 실제 화면/재로드2개 시나리오가 통과했다. 이는 손상·호환 데이터의 복구 검사이며 실제 인식 정확도나 동기화를 검증하는 기능은 아니다.

최종 빌드의 전체140개·품질10개와 기존 저장 실패/재시도·참가자 전달·판정 보류/부분 연습 점수 요약 검사가 통과했다. 두 빌드가 성공했고 별도 읽기 전용 코드 검토에서 추가로 확정된 문제는 없었다. 운영 검증은 작업 계획 기록을 따른다.

## 11/14 추가 보강: 비교 가능한 직전 결과

8마디 리포트는 직전 기록이 있다는 이유만으로 비교하던 동작을 수정했다. 같은 코드 순서·전환 조합/곡 종류·템포·판정 방식·실행 속도일 때만 직전 박자 결과를 비교한다. 모의 판정끼리의 비교에는 모의 결과임을 표시한다. 조건이 다르거나 이전 기록의 설정을 확인할 수 없으면 비교 안내만 보류하며, 직전 결과와 연습 시간은 유지한다.

새 결과에 실행 속도 메타데이터를 기록한다. 도중에 속도를 바꾸면 혼합 조건이므로 비교에 사용하지 않는다. 실제 입력에서 모의 판정으로 명시적으로 전환해 새 시도를 시작할 때는 다른 시도 정보와 함께 다시 초기화한다. 이전 버전 기록의 누락된 설정을 임의로 추정하지 않는다. 처음 연습한 경우와 비교 불가능한 직전 기록이 있는 경우의 문구도 구분한다.

수정 전 서로 다른 조건9개가 잘못 비교되는 것을 실제 리포트 렌더링으로 확인했다. 수정 후 렌더링10개와 모의 표시·처음/이전 기록·비정상 입력 경계 검사가 통과했다. 브라우저의 실제8마디 완주·중간 속도 변경·재로드7개도 통과했다. 기존 전체 검사의 hard→allok 비교 기대는 비교 보류로 바꾸고 직전 기록 보관 검사는 유지했다.

최종 빌드의 전체140개, 장치 복구5개, 패널 정지/속도9개, 리포트 왕복 등3개, 모바일12개와 저장 복구 검사가 통과했다. 일반·단일 파일 빌드와 별도 코드 검토도 마쳤다. 실제 기타 인식률은 이 결과로 확정하지 않는다.

## 남는 제한과 마지막 실기

- 코드 인식은 Em·G·C 음 구성 비교 방식이다. 잡음, 울림, 폰 마이크 특성에 따른 정밀도·재현율 자료가 없다. 임의 기준값 조정으로 정확도가 높아졌다고 주장하지 않는다.
- 실제 자세 판정은 손목·어깨 대상이다. 엄지 판정, 기타 가림, 역광, 좌우 방향, 다양한 체형과 기기 성능은 실기로 확인해야 한다.
- 자동 검사는 Windows Edge 중심이다. 실제 iOS Safari·Android Chrome의 권한·오디오·카메라·잠금·발열은 마지막 실기 범위다.
- 기록은 해당 브라우저의 로컬 저장소다. 계정·기기 간 동기화와 실제 친구 서버는 구현 범위에 포함되지 않는다.

실기는 [팀 테스트 안내](TEAM_TESTING.md)에 따라 마지막에 진행한다. 그 전까지 소프트웨어 오류를 줄일 수 있지만, 이 단계에서 인식 정확도까지 ‘개발 완료’로 표현해서는 안 된다.
