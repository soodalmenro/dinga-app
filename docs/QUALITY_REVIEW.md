# 품질 재검토 — 2026-11-12

## 현재 평가

화면 흐름을 실행할 수 있는 연구용 프로토타입이다. 실제 기타의 코드·박자 인식 정확도와 기타에 가려진 손목의 인식률을 검증한 제품은 아니다. 이전의 정상 경로 중심 자동 검사는 아래의 권한·중단·재시도 오류를 놓쳤다. 자동 검사 통과와 실기 정확도를 구분해서 전달해야 한다.

## 동작 변경과 기록 해석

- 곡 연습 메트로놈은 기본 끔이다. 사용자가 켤 수 있으며 마이크가 켜져 있으면 이어폰 안내를 표시한다. 스피커 클릭음이 연주로 감지되는 위험을 줄이기 위한 설정이며, 실제 기기의 피드백 제거 성능을 측정한 결과는 아니다.
- 마이크 없는 12마디 완주는 점수 없이 완료와 시간을 남긴다. 8마디의 모의 판정은 개발 전달 명세에 따른 기존 정책을 유지한다.
- 모의 판정·중도 종료는 앞으로 최고 기록을 갱신하지 않는다. 이전 버전의 최고 기록은 출처가 없어 실제·모의를 소급 구분할 수 없으므로 삭제하지 않는다.
- 기본 자세 알림은 여전히 정해진 시점에 표시하는 시뮬레이션이다. 실제 자세 판정으로 임의 전환하지 않았다.
- 파트 완료 180초·독립 전환 120초 기록은 기획의 명목 시간 규칙이다. 이번 변경은 중도 종료 시 팝업과 숨김 시간을 제외하는 데 적용한다.

## 검증 근거

`qa/quality-review.cjs`는 Edge 브라우저와 가짜 미디어 장치를 사용해 다음 10개 사례를 확인한다.

1. 권한 무응답 상태에서 수동 출석 후 늦은 허용 응답
2. 연주 복귀 후 늦은 마이크 허용과 네 번의 소리 감지
3. 부모 나가기 팝업 중 내장 전환 연습 정지·재개
4. 최종 레슨 재시도 후 완료 진도와 모의 점수 구분
5. 실제 판정의 부분 100점 최고 기록 제외, 코드·박자 요약 분리
6. 마이크 판정 경로로 완주한 유효 점수의 최고 기록 갱신
7. 백그라운드 전환 후 마디 보존·명시적 재개
8. 팝업 제목·초기 포커스·Tab 순환·Escape
9. 2.3초 프레임 공백의 출석 소리 시간 제외
10. 촬영 카운트 정지·재개와 재촬영 라이브 미리보기

추가로 기존 중단·리포트 왕복, 저장 실패 복구, 자세 모델 실패·시간 초과·자원 해제, 무마이크·모의 판정, 운지·콘텐츠·현재 마디 스크롤, 320·360·390px 화면 검사를 수행한다. 가짜 입력의 성공은 실제 기타 인식률을 의미하지 않는다. 별도 읽기 전용 코드 재검토에서도 수정 후 추가로 확정된 회귀는 없었다.

전체 검사 첫 실행에서는 139개 통과, 카메라 미리보기 검사 1개 실패가 나왔다. 고정 900ms 대기 후 스트림만 확인하던 검사를 실제 영상 프레임 준비(readyState·videoWidth)까지 기다리는 검사로 보강했다. 별도 재촬영 검사는 실제 프레임과 살아 있는 스트림을 확인한다.

최종 Vite 6.4.6 빌드에서 전체 140개와 추가 품질 검사 10개가 모두 통과했다. 일반·단일 파일 빌드도 성공했으며 의존성 감사는 0건이다. 모바일 12개 조합과 기존 예외·저장·자세·콘텐츠 검사는 이 변경 묶음의 검증 과정에서 통과했다.

## 남는 제한과 마지막 실기

- 코드 인식은 Em·G·C 음 구성 비교 방식이다. 잡음, 울림, 폰 마이크 특성에 따른 정밀도·재현율 자료가 없다. 임의 기준값 조정으로 정확도가 높아졌다고 주장하지 않는다.
- 실제 자세 판정은 손목·어깨 대상이다. 엄지 판정, 기타 가림, 역광, 좌우 방향, 다양한 체형과 기기 성능은 실기로 확인해야 한다.
- 자동 검사는 Windows Edge 중심이다. 실제 iOS Safari·Android Chrome의 권한·오디오·카메라·잠금·발열은 마지막 실기 범위다.
- 기록은 해당 브라우저의 로컬 저장소다. 계정·기기 간 동기화와 실제 친구 서버는 구현 범위에 포함되지 않는다.

실기는 [팀 테스트 안내](TEAM_TESTING.md)에 따라 마지막에 진행한다. 그 전까지 소프트웨어 오류를 줄일 수 있지만, 이 단계에서 인식 정확도까지 ‘개발 완료’로 표현해서는 안 된다.
