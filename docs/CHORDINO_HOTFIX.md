# 소리 인식 첫 수정 배포

2026-11-16 팀 테스트 분석,11/17 수정 검증. 기타 대신 타자/두드림으로 진행하는 문제를 확인했다. 큰 백색잡음을 실제 MediaStream으로 입력해 기존 출석이 되는 현상을 RED로 재현했다. 최신 Figma 카메라/UI 수정과 분리한 첫 배포다.

## 변경 범위

- 마이크의 동일 AudioContext·입력 소스를 로컬 Chordino0.6.0 AudioWorklet→Worker→WASM에 연결한다. 인식 실패/로딩/미지원 시 음량 판정으로 자동 복귀하지 않는다. 모의 판정과 마이크 없이 연습은 명시적인 별도 경로다.
- 출석은 안정된 코드가 확인되는 시간을2초 모은다. 소리 크기2초를 대신하며 단일 줄/타자는 출석 근거가 아니다.
- 코드 연주/안 보고 치기/박자는 목표 Em/G/C와 정확히 일치한 새 입력을 센다. Em7·G5·C/E 등 변형을 임의로 정답 처리하지 않는다. 같은 코드의 울림이 남아 있어도 새 타격을 세며, 한 번 친 음의 감쇠·작은 진폭 변화는 중복 입력으로 세지 않는다.
- 준비의 튕겨보기와 곡 시작도 음악적 코드 확인이 필요하다. 준비 단계의 기존 '아무 줄' 문구는 코드 연주에 맞춰 수정한다.
-8마디는 해당 마디 목표 코드가 확인된 입력을 박자 결과에 쓴다.12마디와 친구의 같은 곡 연습은 원래 오디오 시각에 배정한 Chordino 근거로 채점한다. 완주·점수·모의 결과는 구분한다.
- 인식 준비/현재 코드/실패 안내를 화면에 표시한다. 평가 패널에서 상태를 확인할 수 있다. 지연은 코드 분석의 특성이며 박자는 원래 타격 시각에 배정한다.
- 추가 디코딩 대기는0ms, 코드 안정 근거350ms는 유지한다.250ms 추가 대기에서는60BPM의0.8초 울림/0.2초 휴지가 누락돼 이를 재현하고 수정했다.350ms 기준을 낮춰 잡음을 통과시킨 방식은 아니다. 마디 종료 후 최대2초는 늦은 코드 결과를 기다리며 일시정지 중 근거는 차단한다.
- 새로고침 시 기록 삭제, webdriver 자동 우회, 불명확한 코드 강제확정은 적용하지 않았다.

## 팀 재테스트

배포 버전을 확인한 뒤 같은 폰·브라우저로 아래를 비교한다. 카카오 인앱 브라우저 결과와 Safari/Chrome 결과는 따로 기록한다.

1. 출석에서 타자·탁자 두드림·박수·말소리만 낼 때 출석하지 않는지, Em/G/C를 반복 연주하면 출석되는지.
2. Em 연주에서 G/C는 횟수가 늘지 않고 Em 네 번은 늘어나는지. 음을 일부러 끊지 않고 이어 치는 경우도 확인한다. 한 번 친 Em을 길게 울리는 것만으로 네 번 채워지면 오류다.
3. G/C 연주·안 보고 치기·박자에서도 해당 코드만 세는지. 준비 단계도 단일 줄 대신 아는 코드를 친다.
4.8마디 전환과 친구의 곡 연습이 잡음만으로 시작되지 않는지. 실제 코드 연주 후 정답/다른 코드/보류 결과를 확인한다.
5. 허용·거부·다시 시도, 다른 앱 전환 후 재개를 확인한다. 입력이 안 되면 화면의 코드 인식 상태/현재 코드도 함께 캡처한다.

기종/OS/브라우저·앱 JS버전·진입경로·실제로 친 코드·화면 코드/횟수·재현 순서를 전달한다. 키보드 소리를 음악으로 읽는 사례가 나오면 해당 조건부터 다시 재현한다. 원음은 앱에서 저장하지 않는다.

## 아직 확정하지 않은 것

합성 오디오/공식 WASM/Edge 검사는 실제 기타의 인식률을 측정한 것이 아니다. 약한 소리·튜닝·잡음·가려진 운지·초보 연주·iPhone Safari는 팀 기기에서 확인해야 한다. Chordino는 기타 전용 소리 식별기가 아니므로 스피커 음악이나 일부 지속적인 목소리를 코드로 읽을 수 있다. 목표 코드·안정 시간으로 줄이지만 완벽히 배제한다고 주장하지 않는다.

카메라 S7/P1·교정 그림, 캐릭터·위젯·게이지·3분 시나리오는 후속 배포다. 이 첫 수정 배포에 해결됐다고 표시하지 않는다. GPL 고지와 해당 빌드 소스는 앱 평가 패널→라이선스·소스에서 내려받는다.

## 검증 기록

- 큰 잡음으로 출석되는 기존 동작 RED→GREEN. 실제 AudioContext/Worklet/공식WASM을 쓰며 webdriver 자동 우회 없음.
- 연속 Em 네 번이 한 번만 세어지는 현상을 재현하고 새 타격 감지로 수정했다. 실제 합성 스트림에서 네 번=네 번, 길게 울리는 한 음=한 번을 따로 검사한다.
- 절전 중 AudioContext 시계가 멈추는 조건 RED→GREEN. 현재 오디오 블록일 때만 시계 기준을 다시 잡고 경계 이전 근거를 폐기한다. 오래 밀린 음원은 신선한 것으로 바꾸지 않는다.
- 최종 코드 검토의 세 항목(이른 전환 코드 배정, 늦은 마디 결과 유예, 일시정지 중 코드 유입)은 각각 실패 검사 후 수정했다.
- 박자 검사 첫 음 누락 중 하나는 테스트가0박 표시 뒤 음원을 합성하느라 실제 재생을 한 박 늦게 시작한 원인이었다. 음원은 카운트다운 중 미리 만들고0박에 재생하게 수정했으며350ms 안정/정답8박 검사를 완화하지 않았다.
- 최종 화면140/140, 입력 수명/게이트/마디 시각/공식 자산/저장·내보내기 단위 검사, 인식 실패·재시도 검사 통과. 현재 배포/실제 입력 최종 결과는 이어서 기록한다.
-11/17 최종 빌드 `index-jMQIVozL.js`: 실제 AudioContext→Worklet→공식WASM 전체 검사 exit0. 한 번 울림1회/연속4타격4회, 잡음·타격·합성 말소리 출석 부정, 약한Em출석, Em/G/C각각오답0회·정답4회,50/60BPM정답8박,8마디8개정답 통과.12마디 첫Em에G를 의도적으로 넣어 오답 처리하고 나머지11개는 정답, 코드 정확도92%로 검사했다. 이는 합성 입력 시나리오 결과이며 실제 기타 인식률92%라는 뜻이 아니다.
- 인식기 로딩 실패 시 음량 fallback 없음·재시도 복구,320/360/390px 화면12조합, 명시적 모의 UI140개 통과. 배포본 라이선스/해당 소스 SHA일치 검사 통과. 팀 PC Chrome +유튜브 입력과 실제 기타는 배포 후 별도 확인한다.
