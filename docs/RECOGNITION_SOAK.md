# 인식 경계와 반복 사용 검증

2026-11-13. 실기 전에 소프트웨어에서 확인할 수 있는 범위를 확장한다. 실제 휴대폰과 기타의 인식률·지연·발열은 마지막 실기 대상이다.

## 재현한 자세 지속 시간 오류

기존 자세 watcher는 나쁜 자세가 처음 관측된 시각과 다음 결과 시각의 차이로 지속 시간을 계산했다. 중간에 프레임이 멈추거나 추론이 오래 걸리면 관측하지 않은 시간도 1.5초 지속 조건에 포함될 수 있었다. 정상적인 크기의 좌표를 반환하더라도 실제 영상 크기가 0이면 임의의 480×640 크기로 계산하는 경로도 있었다.

수정 기준은 다음과 같다.

- 화면이 보이고 영상 준비·크기가 유효할 때만 계산한다. 결과가 도착할 때도 영상 상태와 크기를 다시 확인한다.
- 이미 처리한 영상 시각은 다시 추론하지 않는다. 같은 프레임을 여러 번 계산해 연속 관측으로 만들지 않는다.
- 새 관측 사이 공백 또는 추론 지연이 1초를 넘으면 기존 지속 시간을 버린다. 이 값은 인식 정확도 보정값이 아니라 오래된 증거를 제외하는 공학적 한도다.
- 유효한 저속 영상은 중복 프레임을 건너뛰되 새 관측 간격이 한도 이내면 지속 시간을 유지한다. 영상이 멈춘 경우와 초당 프레임 수가 낮은 경우를 구분한다.
- 경고 조건인 1.5초 지속, 기본 알림 시뮬레이션, 실제 판정 선택, 알림 간격·횟수 제한은 유지한다.

자동 검사에는 정상 연속 관측, 낮은 프레임 수, 긴 공백, 같은 영상 반복, 영상 준비 중단, 화면 숨김, 늦은 결과, 크기 0을 포함한다. 합성 좌표는 실제 기타에 의한 가림과 체형 차이를 재현하지 않는다.

## 반복 사용과 연속 실행

`qa/repeated-use.cjs`는 한 브라우저 페이지에서 환경 확인 4회, 레슨 진입·종료 6회(일부 마이크 복구 포함), 곡 완주 5회를 실행한다. 화면을 나간 뒤 트랙 종료, 입력용 AudioContext 종료, 입력 리스너 해제, 추론 중지, 화면 잠금 해제를 확인한다. 곡 완료 횟수와 종료 이벤트는 시도마다 한 번이어야 하며 모의 결과는 실제 최고 점수를 갱신하지 않는다.

효과음용 AudioContext는 재사용하며, 사용자 터치에서 다음 입력을 준비한 컨텍스트가 하나 남을 수 있다. 입력에 사용된 컨텍스트와 실제 캡처는 종료돼야 한다. 이 구분 없이 컨텍스트 수만으로 누수라고 판단하지 않는다.

`qa/practice-soak.cjs`는 기본 5분을 가속하지 않고 실제로 기다린다. 활성 오디오·영상 트랙, 입력 컨텍스트, 모델 인스턴스와 동시 추론 수가 늘지 않는지 30초 간격으로 확인한다. 종료 후 캡처와 추론이 멈추는지도 확인한다. 합성 모델과 가상 장치를 사용하며, 힙 메모리 누수의 부재나 저성능 휴대폰의 발열을 입증하는 검사는 아니다.

## 코드 경계와 복구 화면

- `qa/chord-boundaries.cjs`: 지지 비중·후보 차이·구성음 최소 비중의 경계 양쪽을 확인한다. Em/G/C 조합 303개와 입력 배율 제어로 애매한 입력의 판정 보류와 무관한 코드 확정 방지를 검사한다. 크기 배율 불변성은 약한 실제 기타의 감지 성능을 뜻하지 않는다.
- `qa/recovery-layout.cjs`: 320×568, 844×390, 568×320에서 복구 팝업의 가로 잘림과 버튼 조작을 확인한다. 두 조건에서는 팝업 글자 크기를 150%로 늘린다. 운영체제 글자 확대나 Safari 자체 검증을 대신하지 않는다.

## 실행

기본 단위 검사는 Node와 Vite를 사용한다. 브라우저 검사는 Playwright가 필요하며 Edge에서는 `QA_BROWSER_CHANNEL=msedge`를 지정한다.

```text
node qa/pose-observation.cjs
node qa/chord-boundaries.cjs
node qa/repeated-use.cjs
node qa/practice-soak.cjs
node qa/recovery-layout.cjs
```

연속 실행 시간은 `QA_SOAK_MS`로 60,000~1,800,000ms 범위에서 정할 수 있다. 기본값은 300,000ms다. 테스트 시간·장치·브라우저와 결과를 함께 남긴다.

## 마지막 실기

팀원에게는 [팀 테스트 안내](TEAM_TESTING.md)와 배포된 앱을 전달한다. 우선 기종·OS·브라우저, 실제 자세 판정 설정, 조명·폰 각도, 손목·어깨 가림, 정답/오답/보류와 알림 누락을 기록한다. 원음·영상 업로드를 요구하지 않으며 참가자별 JSON으로 실행 버전과 판정 이유를 회수한다. 실기에서 재현된 문제에 따라 기준이나 처리 방식을 보정한다.

## 11/13 검증 기록

최종 소스의 자세 관측 10개 조건, 좌우 손·반사 좌표·유효성·촬영 요구, 코드 판정 경계 3종과 혼합 입력 303개(보류125개), 실제 경과 시간 300,000ms 자원 검사와 기존 전체 빌드 QA140개가 통과했다. 5분 실행에서 캡처 스트림2개·활성 트랙2개·입력 컨텍스트1개·모델1개·최대 동시 추론1개를 유지했고, 총1186회의 합성 추론 후 종료 자원을 해제했다. 이 숫자는 Windows Edge 가상 장치 결과다. 일반·단일 파일 빌드가 성공했고 독립 코드 리뷰에 확정된 중요한 오류는 없었다.

같은 최종 소스에서 반복 UI15회, 자세·카메라 복구, 환경 준비, 품질10개와 장치 복구5개도 통과했다. 배포용 번들의 곡 리포트·참가자 JSON·마이크 재연결 경로를 로컬에서 확인했다.
