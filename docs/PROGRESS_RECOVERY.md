# 단계 저장과 브라우저 이탈 보호

2026-11-14. 실기 전에 레슨 위치와 저장 전 기록을 보호하는 개발 보강이다.

## 레슨 단계 자동 저장

정규 레슨은 단계에 들어갈 때마다 기존 `resume`에 레슨·파트·단계를 저장한다. 앱 안의 나가기를 누르지 않고 새로고침했어도, 홈의 이어하기로 마지막 단계에 돌아올 수 있다. 코스의 곡 연습으로 넘어가기 전에도 해당 진입 위치를 남긴다.

- 파트 완료 시 이어하기 위치를 지우며 완료 표시와 기존 기록은 유지한다.
- 복습·독립 전환 연습은 정규 코스의 이어하기 위치를 덮어쓰지 않는다.
- 단계 위치를 저장하는 기능이다. 단계 안의 소리 횟수, 미완료 곡의 마디별 판정·점수·경과 시간을 자동 복원하지 않는다.
- 저장 실패 시 기존 저장 오류 안내와 재시도를 사용한다. 재시도는 현재 메모리의 최신 단계를 저장한다. 실패를 저장 성공으로 표시하지 않는다.
- 완료 화면에서 단계 건너뛰기를 반복해도 같은 시도의 완료 시간과 완료 이벤트를 다시 추가하지 않는다. 완료 파트를 새로 열어 다시 연습하는 것은 별도 시도로 처리한다.

## 저장 전 브라우저 이탈

진행 중인 레슨과 시작한 곡·전환 연습에는 브라우저의 이탈 확인을 등록한다. 내부 나가기 확인창은 유지한다. 곡 시작 전 대기 화면과 저장된 완료 화면에서는 해당 연습의 이탈 확인을 해제한다. 완료 후에도 앱 데이터 저장 오류가 남아 있으면 보호를 유지하며 재시도 성공 후 해제한다.

이탈 확인을 취소하면 현재 연습에 머문다. 레슨에서는 네이티브 확인창에서 기다린 시간을 연습 시간에서 제외하며, 앱 팝업·백그라운드 일시정지와 겹친 시간도 중복 차감하지 않는다. 명시적 나가기의60초 기준, 완료180초·독립 전환120초 기준은 유지한다.

확인창은 브라우저가 표시하는 표준 문구다. 사용자 조작이 필요하고 모바일 앱 관리자에서 브라우저를 종료하는 경우처럼 이벤트가 실행되지 않는 상황이 있으므로 종료를 완전히 막는 기능으로 표현하지 않는다. 그래서 이탈 확인과 별개로 단계 위치를 저장한다. [MDN의 beforeunload 사용 조건](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)을 따른다.

## 확인 방법과 범위

평가 패널의 레슨 속도를 바꾸면 바꾸기 전 시간은 당시 속도로 유지하고 이후 시간에만 새 속도를 적용한다. 소수 초는 구간별로 버리지 않고 합산 후 마지막에 초 단위로 내린다. 패널·막힘·나가기·브라우저 확인창 대기는 제외한다. 완료180초·독립 전환120초와 중도 종료60초 저장 기준은 유지한다.

`node qa/lesson-time.cjs`는 속도 감소·증가, 여러 구간과 소수 초, 패널·막힘·나가기 대기 제외, 네이티브 이탈 대기, 정확히60초 저장과60초 직전 미저장 등7개 시나리오를 검사한다. 브라우저에서 시계를 제어한 재현 검사이며 실제 기타 입력 검증을 대신하지 않는다.

`node qa/progress-checkpoint.cjs`는 다음을 확인한다.

- 단계 이동→새로고침→이어하기, 완료 후 재로드에서 완료·시간 유지
- 단계 저장 실패→저장 다시 시도→최신 위치 복원
- 완료 저장 실패의 이탈 보호 유지와 복구 후 해제
- 완료 화면의 반복 건너뛰기가 시간과 이벤트를 중복 생성하지 않음
- 복습·독립 전환이 코스 위치를 바꾸지 않음
- 코스 곡 진입 위치를 저장하고 미완주를 완료로 만들지 않음
- 실제 브라우저의 닫기·뒤로가기 확인과 취소, 내부 나가기 뒤 구독 해제
- 확인창에서 대기한 시간의 연습 시간 제외

브라우저 대화를 검증하는 페이지는 명시적 BrowserContext로 생성한다. 설치된 Playwright의 편의 `browser.newPage()` 페이지는 닫을 때 소유 컨텍스트를 먼저 닫아 대화를 건너뛸 수 있어 검사 구조를 분리했다. 이탈 보호를 검증하는 검사 외에, 전체 QA의 의도적인 상태 주입·새로고침은 확인창을 명시적으로 수락한다.

실제 휴대폰의 강제 종료·캐시 복귀 정책과 기타 연주는 마지막 기기 검증 범위다. 서버 동기화나 원음·영상 저장은 추가하지 않는다.

11/14 새 실행 환경에서 신규10개 시나리오, 전체140개, 기존 저장 실패·재시도·품질10개·참가자 전달·나가기 회귀 검사가 통과했다. 실제 배포 파일을 로컬에서 실행해 새로고침 확인·이어하기·완료1회도 검증했다. 두 빌드가 성공했고, 독립 코드 리뷰에서 중요한 오류는 발견되지 않았다. 운영 버전 검증 결과는 작업 계획 기록에 남긴다.
