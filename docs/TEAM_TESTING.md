# 딩가 팀 테스트 안내

[앱 실행](https://dinga-app.vercel.app/) · [비공개 개발 저장소](https://github.com/soodalmenro/dinga-app)

현재 버전은 출석부터 곡 완주·리포트·기록 저장까지 구현돼 있다. 코드·자동 검사로 확인할 작업을 진행한 뒤 실기 검증을 마지막에 수행한다. 카메라 권한·모델 실패·재시도·종료 처리는 자동 검사로 확인했으며, 실기에서는 기타를 든 사람에 대한 인식 정확도와 휴대폰 처리 속도를 확인한다.

## 카메라 테스트 설정

1. 폰에서 앱을 연다. 화면 오른쪽 위를 빠르게 세 번 눌러 평가 패널을 연다.
2. 참가자 번호를 정하고, 화면 구성은 ‘아이디어 반영’, 자세 알림은 ‘실제 판정’, 속도는 ‘×1’로 둔다.
3. 출석한다. 기타가 없어도 ‘마이크 없이 출석하기’로 진행할 수 있다.
4. 학습 → 코스 이어하기 → Em 코드 연습의 파트 1을 연다. 설명에서 다음으로 넘어가 카메라를 허용한다.
5. 폰을 고정하고 두 어깨와 코드 잡는 팔의 팔꿈치·손목이 카메라에 들어오도록 위치를 조정한다.

기본 설정 ‘정해진 시점’은 연주 단계 5초 뒤에 알림을 띄운다. 실제 자세 인식을 시험할 때는 반드시 ‘실제 판정’을 선택한다. 현재 실제 판정 대상은 왼손 손목과 어깨이며 엄지 위치는 판정하지 않는다. 기준값은 실기 보정 전이다.

## 확인 순서

필요하면 먼저 홈 → ‘연습 환경 확인’에서 소음 2초와 시험 연주 2초를 확인하고 입력 기준을 적용한다. 실제 기타가 없으면 입력 확인은 건너뛴다. 카메라 확인에서는 촬영 위치만 준비하며 실제 자세 알림 설정은 바뀌지 않는다. [사용 순서와 임시 기준](PRACTICE_ENVIRONMENT.md)을 참고한다.

| 항목 | 확인할 결과 |
|---|---|
| 편한 자세로 연주 | 카메라가 켜지고 과도한 알림이 없는지 확인 |
| 손목을 카메라 밖으로 옮김 | Em에서는 ‘손목이 안 보여요’ 또는 몸 미인식 안내 확인 |
| 작은 범위에서 손목 방향 변경 | 자세 변화와 손목 알림의 대응 확인. 판정은 같은 상태가 1.5초 지속돼야 발생 |
| C 코드 연습의 연주 단계 | 어깨 위치 변화와 알림의 대응 확인 |
| 카메라를 가림·다시 드러냄 | 미인식 안내 후 추적이 복구되는지 확인 |
| 판정 실패 표시 | 카메라 미리보기를 눌러 ‘자세 판정 다시 시도’ 실행 |
| 권한 거부 | ‘카메라 다시 켜기’로 복구 가능한지 확인. 브라우저에서 영구 차단했다면 사이트 권한을 직접 변경 |
| 완료·나가기 | 카메라 미리보기가 사라지고 폰의 카메라 사용 표시가 꺼지는지 확인 |

알림 사이에는 15초 간격이 있고 파트당 최대 3회 표시된다. 새 판정 세트를 시험할 때는 파트를 다시 연다. 연습하지 않는 화면에서도 카메라 표시가 계속 남거나 화면이 멈추면 별도 오류로 기록한다.

## 결과 전달 양식

곡 연습을 확인할 때는 다음도 함께 기록한다. 메트로놈은 기본 끔이며, 켜려면 이어폰을 사용한다. 모의 판정·중도 종료 점수는 최고 기록을 갱신하지 않는다. 마이크 없이 완주하면 점수는 ‘측정 안 됨’으로 남는다. 다른 앱으로 전환했다 돌아온 경우 계속하기를 눌러야 연습이 이어진다.

‘판정 어려움’은 소리는 감지했지만 코드를 확정하지 못한 상태다. 이 마디는 오답으로 계산하지 않으며, 코드 정확도와 종합 점수는 보류된다. 박자 결과와 완주 진도는 남는다. 올바르게 쳤는데 보류된 경우에도 코드·템포·주변 소음·폰 위치를 함께 기록한다. [판정 기준과 합성 검사 한계](CHORD_RELIABILITY.md)를 참고한다.

- 기종 / OS / 브라우저
- 레슨 / 파트 / 자세 알림 설정
- 폰의 방향·위치 / 조명 / 기타를 든 손목이 보였는지
- 시험한 행동 / 기대한 반응 / 실제 화면 문구와 알림
- 재현 여부 / 지연·발열·화면 멈춤 여부
- 평가 패널 → 파일 저장 범위 ‘현재 참가자’ → ‘JSON 저장’ 파일. 브라우저에서 실제 저장됐는지 확인한다.
- 파일 저장이 어려우면 같은 JSON 미리보기를 직접 복사한다. 기존 ‘복사’ 버튼은 전체 참가자의 행동 기록 배열이다.

저장 공간이 부족하거나 브라우저가 저장을 차단하면 앱 상단에 안내가 표시된다. ‘저장 다시 시도’로 복구를 확인하고, 복구가 어려우면 창을 닫기 전에 행동 기록을 복사한다. 저장이 실패한 세션의 행동 기록은 해당 창이 열린 동안 복사할 수 있다.

행동 기록만 저장에 실패한 경우에도 평가 패널에 임시 기록 안내가 표시된다. 참가자마다 파일을 회수한 뒤 초기화하고, 최근4000건 보관 상한 안내가 보이면 이전 기록이 일부 없을 수 있음을 함께 기록한다. 새 곡 종료 기록에는 마디별 판정 이유가 포함된다. [파일 스키마와 검증 한계](EVALUATION_EXPORT.md)를 참고한다.

우선 기타 없이 카메라 연결·가림·종료를 확인하고, 기타를 든 뒤 같은 순서로 반복하면 악기로 관절이 가려질 때 생기는 차이를 비교할 수 있다. 저장되는 행동 기록에는 판정 상태와 알림이 포함되며 영상은 저장하지 않는다.

## 마지막 실기에서 장치 복구 확인

- 연습 중 마이크 입력을 중단할 수 있는 기기에서는 입력을 끊고 진행이 멈추는지 확인한다. 다시 연결해도 계속하기 전에는 진행하지 않아야 한다.
- 12마디는 완료 마디를 유지하고 중단된 마디를 다시 연주한다. 8마디에서 마이크 없이 전환하면 새 모의 시도로 시작하는지 확인한다.
- 다른 앱 전환과 입력 중단을 함께 겪은 뒤 연결·계속하기로 재개한다. 멈춘 동안 성공 횟수나 마디가 늘지 않아야 한다.
- 카메라 중단 뒤 재시도, 촬영 카운트다운 중 중단, 화면 복귀 뒤 카메라/마이크 사용 표시와 발열을 확인한다.

기기·브라우저·중단 방법·안내 문구·재현 순서를 함께 남긴다. 자동 검증 범위와 코드 전환의 합성 검사 한계는 [입력 중단 복구](MEDIA_RECOVERY.md)에 있다.

실제 자세 판정에서는 잠시 멈춘 화면이나 긴 추적 공백 뒤 첫 결과만으로 즉시 자세 경고가 생기지 않아야 한다. 저성능 폰에서 영상은 움직이지만 경고가 잘 발생하지 않는 경우에도 기종·지연과 함께 기록한다. 1초가 넘게 지연된 결과는 현재 자세로 사용하지 않는 보수적인 처리다. [관측 경계와 반복 검사](RECOGNITION_SOAK.md)를 참고한다.

## 최종 실기 기록 묶음

처음에는 한 기기·한 참가자 번호로 조건을 바꿔 기록한다. 다른 기기 결과를 합쳐 인식률 하나로 만들지 않는다.

| 순서 | 조건 | 함께 남길 내용 |
|---|---|---|
| 1 | 기타 없이, 그다음 기타를 들고 같은 위치 | 손목·어깨 표시 변화, 가림 안내, 정상 자세에서 불필요한 알림 |
| 2 | 폰 각도·거리·조명을 한 가지씩 변경 | 어떤 조건에서 추적이 끊기고 다시 보이는지 |
| 3 | Em/G/C를 구분해 연주 | 친 코드·템포, 화면의 정답/오답/보류, 약한 소리·주변 소음 여부 |
| 4 | 앱 전환·권한 또는 장치 중단·재연결 | 중단 중 진도 증가 여부, 안내 문구, 계속하기 후 재개 여부 |
| 5 | 한 세션 완료와 파일 회수 | 완주·리포트·중복 기록 여부, 참가자별 JSON 실제 저장 여부, 지연·발열 |

자세 알림의 15초 간격·파트당 최대 3회 제한 때문에 반복 동작마다 알림이 나오지는 않는다. 새 비교 조건을 확인할 때는 파트를 다시 열고 설정을 함께 기록한다. JSON만으로 실제 친 코드나 가려진 부위를 알 수 없으므로 위 관찰 메모도 함께 전달한다.
