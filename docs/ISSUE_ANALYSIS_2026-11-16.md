## 전달 패치에서 그대로 채택하면 안 되는 항목

1. 실패하면 음량 판정으로 돌아가는 자동 fallback은 A1을 다시 만든다.
2. webdriver 감지로 인식기를 끄면 기존 테스트 통과가 실제 인식 검증이 되지 않는다.
3. main.jsx의 freshStart는 새로고침 때 진도/출석/연습 기록을 삭제한다. 사용자 요청 없는 저장 정책 변경이므로 기본 적용하지 않는다.
4. sameChord는 power5·7th·6th·전위까지 같은 코드로 인정한다. 지정 Em/G/C와 어떤 변형을 인정하는지 명시하고 검사해야 한다.
5. worker 원본 음원 시각(atMs/nowMs)을 읽지 않고 수신 시각만 신선도로 쓰면 밀린 오디오가 현재 코드가 될 수 있다.
6. 패치 Song은 여전히 주로 박자 결과이며 모든 목표 코드 정답을 증명하지 않는다. 패치 문서도 박자/전환/곡 음원 테스트 미실행을 밝힌다.
7. 공개 녹음1000개/98% 등은 작성자 보고다. 음원·재현 절차를 받아 이 환경에서 다시 실행하기 전 우리 검증 결과로 쓰지 않는다.
8. 기존 여러 파일 전체 교체는 최신 복구·진도·정책을 덮어쓸 수 있다. 필요한 변경만 병합한다. GPL 고지와 해당 소스 제공 경로도 배포 전에 정리한다.

## 검증·배포 방식의 수정

- 기존 UI140개는 명시적 allok 모의 검사였다. 이것은 인식기·기타 정확도 증거가 아니다. 실제 오디오 경로 테스트를 별도로 필수화한다.
- 마지막 소스 joint검사는 일부 통과했으나 built8마디 진입 타임아웃과 chord-browser 후반 타임아웃이 남아 있다. 종료코드0이 없는 전체 성공으로 보고하지 않는다.
- 첫 배포: 소리 오인식 공통 경로. 다음: Figma 카메라 흐름/교정. 그다음: 나머지 UI/실험 흐름. 안전하게 분리 불가능한 변경은 함께 검증하되 상태를 밝힌다.
- 묶음별 버전/변경/통과·미확인/팀 재테스트3–5항목을 전달한다. 팀 메시지는 사용자가 직접 전달하며 자동 발송하지 않는다.
- 재테스트 오류는 기기/브라우저/진입경로/친코드·잡음/화면결과/배포버전으로 묶어 재현→수정→같은 입력 재검사한다. 아이폰Safari는 별도 실제기기 항목이다.
